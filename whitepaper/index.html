Technical Whitepaper · Draft 1.0 · July 2026

CLOISTER

Confining documents against machine ingestion — a four-layer architecture combining post-quantum sealed envelopes, posture-gated decryption, machine-hostile rendering, and collusion-resistant leak attribution.

Once a file's bytes reach a language model, nothing can un-read them. Every serious defence must therefore act before that moment, or make the act attributable afterwards. CLOISTER does both. It replaces the industry's identity-based question — who is opening this document? — with a posture-based one: does the runtime asking for this key have any path by which the plaintext could leave? Keys are released only into a process with no network egress, no clipboard, no capture surface and no debugger. When a document must nonetheless travel, its text layer is replaced by a fluent, per-recipient decoy, so automated extraction pipelines terminate confidently on the wrong document — and any copy that escapes carries a fingerprint that names the leaker from a single paragraph.

This paper specifies the architecture, reports measurements from a working proof of concept of all four layers, and is explicit about the one thing no system of this kind can prevent.

Executive summary

The market has answered a question nobody asked. A well-funded new category of "AI data-loss prevention" now sits at network egress points and inside managed browsers, watching for the moment an employee pastes something into a chatbot. That control works exactly as long as the file stays on a managed device, inside a managed browser, on a managed network. The professor emailing an exam, the associate sending a draft to co-counsel, the researcher sharing a preprint under embargo — none of them are protected by any of it.

CLOISTER starts from a different premise: protection has to travel with the document, and the document has to be hostile to machines while remaining faithful to people. Four layers, each independently deployable:

  • P1 — The Envelope. A hybrid post-quantum sealed container (X25519 + ML-KEM-768) whose content key is derived over a digest of a runtime posture policy. Downgrading the policy destroys the key, even for an adversary holding the distributor's signing key. Measured: 1,660 bytes of constant overhead, 636 MB/s unseal.
  • P2 — The Membrane. Keys are released only into a process that has already, irreversibly, given up the ability to leak: empty network namespace, 16 egress-related syscalls returning EPERM, no ptrace, no /proc/pid/mem, capture-excluded window surface. The filter survives execve, so it also covers an agent runtime or MCP server that attaches downstream. Measured: no detectable rendering overhead.
  • D — Semantic Chaff. When a document must leave the perimeter, CLOISTER decouples what a human sees from what a machine reads. The rendered glyphs are the true document; the text layer is a fluent, length-congruent, per-recipient decoy. Measured: standard extraction pipelines recover 0 of 24 probed sensitive terms and cannot detect that they were fooled — the decoy's compression profile sits inside the natural-language band, whereas classic gibberish-producing tricks are conspicuously anomalous.
  • T — Traitor Tracing. Every copy carries a Tardos codeword embedded redundantly across independent channels. The fingerprint rides two independent channels: the decoy itself, and a sub-perceptual displacement of inter-word spacing that survives being photographed. Measured: with a redundancy schedule of 40, a leaked fragment as small as 5% of the document names at least one of five colluders with probability at least 0.96 against the worst of five collusion strategies, with zero false accusations across 3,000 trials.

Two more layers followed. For the academic case, one that inverts the problem: rather than trying to stop a student feeding an assignment to a model, attest the human writing process cryptographically, disclosing only zero-knowledge predicates over an edit trail that never leaves their device (§4.6, measured in §5.8). And Layer V, which attacks optical capture by exploiting how displays are sampled rather than how pages look. It defeats a single screenshot on any platform with no help from the operating system, and with a shutter at the reader it reduces an ordinary camera's capture to provably uniform grey (§4.7, §5.9).

The honest part, stated once, up front

A person who is authorised to read a document can always photograph the screen, retype it, or dictate it. CLOISTER does not prevent that and no system can. What it does is close every low-effort, high-fidelity, unattributable path — which is where essentially all real incidents live — and guarantee that whatever escapes through the remaining high-effort paths is traceable. Section 2.4 states this as a formal property rather than a slogan.

1  The problem is the invisible moment

The user's own framing was correct and is worth restating precisely, because it rules out most of the market's answers: a model just reads the bytes. There is no instruction you can embed in a file that reliably stops a competent inference pipeline from processing it. Prompt-injection-style "do not read this" markers are unreliable against hardened systems, are trivially stripped, and — as Section 10 argues — are an attack on a third party's system rather than a defence of your own. Content-side pleading does not work.

What makes AI ingestion different from ordinary leakage is not the reading. It is that the moment of ingestion is invisible and unattributable. A document dragged into a chat window leaves no trace in the document's own history, produces no access-log entry the owner can see, and — once the model has answered — is indistinguishable from the user having simply read the file. Traditional confidentiality controls assume that copying leaves evidence. Here it leaves none.

1.2 The 2026 ingestion surface

Enumerating the actual paths matters, because a control that covers three of them and misses the other seven is not a control. As of mid-2026 a document reaches a model through:

Deliberate, user-initiated. Upload into a consumer chat interface; paste into a chat box; a browser-resident assistant reading the active tab; "explain this document" in a PDF reader.

Ambient, platform-initiated. Productivity-suite assistants indexing document stores by default; OS-level assistants that periodically capture the screen; on-device NPU models on "AI PC" hardware; search indexes that now embed document content into vector stores.

Agentic, machine-initiated. Coding assistants that read an entire repository for context; autonomous agents with filesystem tools; Model Context Protocol servers granted directory access; CI pipelines that summarise artefacts.

Incidental. Screenshot-to-model workflows; email integrations; a colleague's device that is less controlled than yours; a third-party vendor's processing pipeline.

The agentic column deserves emphasis because it is both the newest and the least governed. MCP's rapid adoption has produced a steady stream of file-exposure vulnerabilities: sandbox-escape and symlink-bypass flaws in the reference filesystem server (CVE-2025-53109 / CVE-2025-53110), a command-injection flaw in mcp-remote with several hundred thousand downstream installs (CVE-2025-6514), prompt-injection-driven exfiltration of private repository contents through an over-privileged token, and a 2026 design flaw in the STDIO transport producing a cluster of further CVEs.[7][8] The Cloud Security Alliance characterised the situation in May 2026 as systemic rather than incidental, and the NSA has published protocol-specific guidance.[9] The relevant point for this paper is not that MCP is unusually insecure — it is that the file-reading party is increasingly not a person, so controls premised on user intent have no purchase.

2.2 The analog hole, and the narrower thing usually confused with it

These are two different problems and conflating them cost this project a draft.

The analog hole proper is the reader's own eyes, memory and hands. Retyping a paragraph, dictating it, or simply remembering it cannot be prevented by cryptography, by an operating system, or by a document format. That channel is open permanently and no part of this paper claims otherwise.

Optical capture — a screenshot, a photograph, a video recording — is a different matter, and treating it as part of the analog hole was a mistake. It is mediated by a device whose sampling behaviour differs from the eye's in ways that are structural rather than perceptual, and §4.7 exploits that difference. Some of these paths close completely; one closes with an exact zero-information guarantee; others do not close at all. §5.9 says which is which.

What is worth noticing is how bad the analog hole is for the adversary, and CLOISTER is designed to keep it bad. It is slow, it does not scale past a few pages, it produces transcription errors, and — critically — a photograph of a CLOISTER-rendered page still carries the kerning fingerprint, so even the paths that stay open stay attributable (§5.6). The design goal is to make the analog hole the only hole, and to make using it expensive and traceable.

2.3 What we are protecting against, precisely

The threatened event is not "a model reads the text." It is:

Threat event

A complete and faithful copy of the document's semantic content is transferred into an inference system, at low marginal effort, without the owner's authorisation, in a manner that is not attributable to a specific recipient.

Each italicised qualifier is a lever. Remove completeness and the model's answer is wrong. Remove fidelity and the model's answer is wrong in an undetectable way — which is worse for the adversary. Raise effort and most incidents simply do not happen, because they are acts of convenience, not espionage. Remove non-attributability and the deterrent becomes real, because consequences become assignable.

2.4 The security property, stated formally enough to argue with

Let D be a document, R the set of authorised recipients, and Ext an extraction procedure available to an adversary. CLOISTER aims at:

P1 (No cheap faithful path). For every Ext whose marginal cost is within a small constant of "open the file and read the bytes," the semantic content recovered from a CLOISTER artefact is negligible.

P2 (Posture precedes plaintext). No content key is derivable except by a process whose runtime posture satisfies the policy digest bound into the key derivation. Policy downgrade is equivalent to key destruction.

P3 (Attribution under collusion). For any copy or fragment recovered by a coalition of at most c recipients, the tracing algorithm outputs a member of that coalition with probability 1 − ε₂, and accuses a non-member with probability at most ε₁, for parameters chosen by the distributor.

P1 and P3 are measured in Section 5. P2 is enforced by construction and tested adversarially, including against an attacker who holds the distributor's signing key. Note what is not claimed: nothing about A4, nothing about human memory, and no unconditional statement about vision models — Section 5.4 reports exactly how well the vision path works, because pretending otherwise would be dishonest.

2.5 Explicit non-goals

  • Preventing a determined human from transcribing content they may lawfully read.
  • Defending a device whose kernel or hypervisor is under adversary control.
  • Detecting whether a given piece of text was written by a model — a different and, we argue in §4.6, poorly posed problem.
  • Interfering with, degrading, or injecting instructions into third-party AI systems. See §10.2.
  • Preventing lawful discovery, regulatory inspection, or accessibility use. The design must make authorised access easier, not harder, or it will be switched off.

3  Five design principles

1 · Bind keys to posture, not to identity

The question "who are you?" is answerable by a compromised machine. The question "can plaintext leave the process you are about to become?" is answerable only by the platform, and is the question that actually matters. Every access decision in CLOISTER is a statement about the runtime, with identity as one input among several.

2 · Fail closed, and make the failure cryptographic rather than procedural

A policy check that a client could skip is not a control. CLOISTER folds the policy digest into the key-derivation transcript, so a client that ignores the policy derives a key that does not decrypt anything. The enforcement is not "the viewer refuses"; it is "the mathematics refuses."

3 · Degrade for machines, never for humans

Any measure that makes a document harder for a legitimate reader — including a reader using a screen reader or a magnifier — will be disabled by users within a week. The chaff layer is therefore visually lossless: the rendered page is pixel-for-pixel the true document. Accessibility is handled by exposing a genuine accessible text channel to attested assistive technology (§10.3), not by degrading the page.

4 · Prefer a plausible wrong answer to an obvious refusal

This is the least obvious principle and the one that most distinguishes CLOISTER from prior extraction-hardening work. An automated pipeline that receives garbage knows it received garbage, and escalates — to OCR, to a vision model, to a human. A pipeline that receives fluent, plausible, correctly-shaped text stops. Section 5.4 measures the difference: classic glyph-permutation output is statistically conspicuous, and CLOISTER's decoy is not.

5 · Assume the perimeter has already failed, and price the leak

Every copy is unique from the moment it is created. This costs nothing at distribution time and converts the eventual, inevitable leak from an unresolvable mystery into a named individual — which is the only mechanism that has ever reliably changed human behaviour around confidential material.

4  Architecture: four layers

4.1 Composition, and why each layer is insufficient alone

The layers are deliberately redundant, because each fails differently. The envelope alone is defeated the instant an authorised user opens it on a permissive machine. The membrane alone is irrelevant once the file is copied to a device without the runtime. Chaff alone is defeated by a vision model. Tracing alone prevents nothing. Composed, an adversary must defeat a cryptographic binding, a kernel-enforced information-flow boundary, a rendering-layer divergence, and a collusion-resistant code — and the last one has no technical defeat, only the choice not to leak.

4.2 Layer P1 — The Envelope novel binding

A CLOISTER envelope is a COSE/CBOR structure with three parts: a policy, a key-encapsulation block, and an AEAD-protected body. The content key is derived as:

ss   = HKDF-SHA384( ss_X25519 ‖ ss_MLKEM768 ‖ ct_X25519 ‖ ct_MLKEM768 ‖ H(policy) ‖ suite )
KW   = AES-256-GCM(ss)  → wraps CK,   AAD = H(policy)
BODY = AES-256-GCM(CK)  → wraps D,    AAD = H(header)

Why hybrid, and why these parameters. ML-KEM (FIPS 203) is the NIST standard key-encapsulation mechanism; ML-DSA (FIPS 204) and SLH-DSA (FIPS 205) are the standardised signature schemes, with FN-DSA (FIPS 206) still in draft as of this writing.[3] We use ML-KEM-768 concatenated with X25519 rather than either alone: the combiner is secure if either primitive survives, which protects against both a future quantum adversary and an implementation break in the much newer lattice scheme. Both ciphertexts are bound into the transcript, following the same rule that governs the TLS hybrid designs — otherwise an adversary who can maul one ciphertext can produce a related key.

For the legal constituency this is not speculative hygiene. Documents whose confidentiality must hold for decades are precisely the harvest-now-decrypt-later target, and an envelope is a self-contained ciphertext that an adversary can simply keep.

The policy digest is load-bearing. H(policy) appears twice: inside the KDF transcript and as AEAD associated data. This is the mechanism behind principle 2. An adversary who edits the policy to remove egress_blocked does not obtain a permissive envelope; they obtain an envelope whose key derivation no longer reproduces the wrapping key. Section 5.2 verifies this holds even when the adversary also controls the distributor's signing key — signature stripping is not a bypass, because the signature was never the enforcement.

Policy contents. Attribute predicates (matter number, role, institution), a posture requirement set, a validity window, a fingerprint-seed identifier, and a transparency-log endpoint. Attribute-based access is expressed as predicates evaluated by the local broker against verifiable credentials; we deliberately do not put ciphertext-policy attribute-based encryption on the critical path. CP-ABE is elegant and would let the ciphertext itself carry the policy, but practical post-quantum ABE is not production-ready, and a scheme whose security we cannot defend to a court is worse than a predicate check plus a signature. It remains a roadmap item (§12).

Leases make revocation real. The envelope never contains a permanently-usable key. The broker issues a lease — a short-lived token, sealed to the device's platform root of trust, that the membrane must present to re-derive the content key. Offline work is supported by lease duration, not by permanent release. Revocation then means "stop issuing leases," which actually works, unlike revocation in identity-based IRM where the recipient already holds a usable key.

Auditability. Every lease issuance is appended to a tamper-evident Merkle log in the manner of certificate transparency, with inclusion proofs returned to the requester. This is what converts "we think nobody opened it" into a defensible statement — the property that legal and compliance buyers actually pay for, and one that no gateway product can offer because gateways do not see access that happens off-network.

4.3 Layer P2 — The One-Way Membrane novel application

Decentralised information-flow control has a long research lineage — Asbestos, HiStar, Flume, Laminar — which never achieved adoption because it demanded that applications be rewritten against a new label model. CLOISTER's contribution is not the taint concept; it is the observation that decryption is a natural, narrow, application-agnostic taint source, and that the adversary of interest (an inference pipeline) needs a fat, easily-identified channel: a network socket, a clipboard, or a screen capture. You do not need whole-system label propagation to stop that. You need one process, launched already-confined, that never had those channels to begin with.

Ordering is the whole design. Posture is proven, then the key is derived. A sandbox applied after decryption protects nothing, because the plaintext already exists in a process that could have leaked it. In CLOISTER the reader process irreversibly enters the membrane first, then presents the resulting posture evidence to obtain the key.

What the membrane removes. On Linux, in the proof of concept: an empty network namespace (no interfaces, no routes, no resolver), a private IPC namespace, a seccomp-BPF filter that returns EPERM for sixteen syscalls covering socket creation of every address family, connect/bind/listen/accept, all send/receive variants, ptrace, and process_vm_readv/writev, plus PR_SET_DUMPABLE 0 to close same-uid /proc/pid/mem reads and PR_SET_NO_NEW_PRIVS to prevent privilege re-acquisition. The filter is inherited across execve, which is what makes it cover the real renderer and any agent process that tries to attach itself downstream.

Landlock where available. Linux's unprivileged Landlock LSM is the right long-term substrate: filesystem scoping from ABI 1 (kernel 5.13), TCP bind/connect restrictions from ABI 4, abstract-UNIX-socket and signal scoping from ABI 6, and UDP rules at ABI 10.[1] That progression matters because it closes exactly the lateral channels a seccomp filter handles bluntly. The kernel in our test environment (6.18.5) was built without Landlock, which the implementation detects and reports rather than silently skipping — a detail worth stating, because "we applied a sandbox" claims should always be verified at runtime rather than assumed from a kernel version.

Capture exclusion. The screen is a channel, and in 2026 it is an increasingly automated one. On Windows, SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE / WDA_MONITOR) is the documented mechanism by which a window's content is withheld from capture, and Microsoft names it as the way an application excludes itself from Recall snapshots.[4] Recall is opt-in and shipped generally in April 2025 on Copilot+ hardware, which means a document owner cannot assume it is off on a recipient's machine — the exclusion call is not optional hardening, it is a requirement. macOS provides an equivalent window-sharing exclusion; Wayland can deny capture through the portal; X11 fundamentally cannot, and CLOISTER refuses to open protected content under a bare X11 session rather than pretend otherwise.

4.4 Layer D — Semantic Chaff novel

This layer applies when prevention is impossible by construction: the document has to be emailed to opposing counsel, posted to a course site, or filed with a court.

The mechanism. In a PDF, what a human sees and what a machine reads travel through two independent channels: glyph selection (via the font's CIDToGIDMap) and character reporting (via the ToUnicode CMap). Nothing in the format requires them to agree, and no consistency check can detect disagreement without rasterising the page and running OCR. CLOISTER builds a CIDFontType2 in which the CID space is expanded so that each distinct (visible glyph, reported character) pair receives its own CID. The page renders the true document; every text extractor reports the decoy.

The decoy is congruent, not random. This is the part that matters. The decoy is generated to be geometrically identical to the true document — same word count, same per-word character lengths, same punctuation positions, same capitalisation pattern — and composed of real English words drawn from an innocuous topical lexicon. The word choice is driven by a keyed PRF over (recipient identifier, word index), which gives the decoy a second job: it is itself a per-recipient fingerprint. Recovering the decoy identifies which copy was ingested. One artefact, two functions — degradation and attribution — and the second is free.

Where the proof of concept is weaker than the design

Our decoy generator selects length-matched real words from a topical lexicon, so the output is lexically real and structurally perfect but not grammatical — it reads as word salad on close inspection. Production should generate the decoy with a constrained-decoding language model under the same length and punctuation template, keyed identically, producing fluent prose. This is straightforward and we have not built it. Section 5.4 nonetheless shows that the current output is already statistically indistinguishable from natural language by the measure a pipeline would plausibly use.

Why not just strip ToUnicode? Because that is the prior art, and it produces gibberish, and gibberish is a signal. Section 5.4 quantifies this: gibberish sits far outside the compression profile of natural language, so a competent pipeline detects it and escalates to OCR — which recovers everything. The chaff approach removes the escalation trigger.

Additional degradation options, deployable per-policy: reading-order permutation in the content stream; per-page re-keying so that a single recovered mapping does not compromise the document; homophonic expansion of the CID space so that classical frequency analysis of the reported text is starved; and raster-only pages for the highest sensitivity tier. We regard raster-only as a last resort because it is hostile to accessibility.

4.5 Layer T — Traitor tracing and the ingestion oracle

The code. Every distributed copy carries an m-bit codeword from a symmetric Tardos probabilistic fingerprinting code.[10][11] Tardos's construction is the right choice because its length is O(c² log(1/ε₁)) — independent of the number of recipients except logarithmically — and because it is provably collusion-resistant under the marking assumption, meaning a coalition that compares its copies and constructs a hybrid still cannot escape. The original constant was 100 c² ln(1/ε₁); refinements bring the practical constant near the asymptotic optimum of π²/2 ≈ 4.93, which is what we use.

The redundancy schedule. A standard traitor-tracing deployment assumes the whole work leaks. The AI threat model does not: the canonical incident is someone pasting two paragraphs into a chat box. A codeword laid out once across a document is starved by such a fragment. CLOISTER therefore embeds each code bit at R independent locations, so that a fragment of relative size s yields Binomial(R, s) observations per bit, resolved by majority vote. Section 5.5 measures the effect and it is large: choosing R for the shortest fragment you care about is the difference between tracing nothing and tracing a single paragraph.

The ingestion oracle withdrawn. Tracing answers "whose copy is this?" once you hold the leaked text. A separate question is "did model M ingest document D at all?" An earlier draft of this paper proposed answering it by probing a suspect model for the document's canary, on the theory that a document seen in training leaves a detectable trace. We built the measurement and the answer is no, for two independent reasons — one empirical and one that should have been obvious without an experiment. §5.7 reports both. The component is withdrawn from the architecture rather than carried as future work.

4.6 Layer A — Authorship provenance: inverting the academic problem novel; now implemented, §5.8

For assignments, the preventive framing is partly wrong. A professor's real requirement is not "the student must not be able to feed this to a model" — it is "the submission must be the student's own work." Those are different claims, and the second is provable while the first is not.

AI-text detection attempts the second claim by inspecting the artefact, which does not work: the signal is weak, the false-positive cost is a wrongly accused student, and the bias falls on non-native English writers.[13] Vanderbilt disabled Turnitin's detector for precisely this reason.[12]

The alternative is to attest the process. A CLOISTER-aware editor maintains a hash-chained edit trail and emits a signed credential asserting verifiable properties of it — incremental character-level authoring, no bulk insertion above a threshold from an unattested source, plausible inter-keystroke timing distribution, revision count — bound to the submission's hash in the manner of C2PA content credentials. The professor verifies a credential rather than running a classifier. A student who writes normally passes automatically; a student who pastes 2,000 characters from elsewhere produces a credential that says so, without anyone inspecting their prose style.

The privacy problem, and the answer. A keystroke log is surveillance. No student should hand one to an institution, and no institution should want custody of one. The design therefore commits to the trail locally and discloses only predicates over it: the credential proves "no single insertion exceeded N characters" without revealing the text, the timings, or the revision history. This is implemented and measured in §5.8 — the zero-knowledge layer turned out to need no general-purpose proving system, only Pedersen commitments and range proofs over a handful of committed integers. §10.1 treats the ethics, which we consider a first-order design constraint rather than a compliance afterthought.

4.7 Layer V — The display novel; partial

Every spatial defence against OCR has lost. CAPTCHA-style distortion, adversarial perturbation, microtype: each degrades the page for the reader at least as much as for the machine, and vision models keep improving. So this layer does not attack the image. It attacks the sampling.

The asymmetry. A human integrates incident light continuously. A screenshot captures one composited frame. A rolling-shutter sensor integrates a different short slice per scanline. Those gaps follow from how framebuffers and CMOS sensors work, not from any property of perception that a better model could erode.

Construction 1, against the screenshot. Render the page as the time-average of two frames, F1 = L + d and F2 = L − d for a zero-mean mask. Confine the content to luminance [1/3, 2/3] and both frames stay in range, so the average is exact rather than approximate. The eye integrates the pair and reads the document; a screenshot captures one frame. This needs no cooperation from the operating system, which matters because that is exactly what is unavailable on bare X11 and in a web viewer (§6).

Three constructions that failed, and why

Making the mask a second document failed — overlaying text of opposite polarity does not destroy glyph structure, and OCR reads straight through it (recovery 1.000). A block-structured mask survived high-pass filtering but fell to cell-median subtraction once the grid was aligned (0.973–1.000), and the grid is about 256 brute-force guesses scored by "does this read as English". A dense text-shaped mask fell to a four-level classifier (1.000), because near-binary content plus near-binary mask sums to four distinguishable levels and the map back to ink is injective.

The general reason none of them can work: mask amplitude is bounded by display headroom, headroom trades directly against the contrast the reader needs, so per-frame signal-to-mask is about 1 — and OCR beats that by aggregating over a glyph's many pixels. Lowering content contrast to widen the mask lowers it for the reader too, because the reader sees the average. Single-frame secrecy is not achievable at human-readable contrast. Construction 1 therefore defeats off-the-shelf OCR and raises cost; it is not secure.

Why no display-only scheme beats a recording. Suppose the display is a function of the document and time alone, and the adversary records every frame. The reader's retina integrates light over some window to give R(W). The adversary holds every frame, so the adversary can compute R(W) for any window, including the reader's. Anything legible to the reader is legible to the recording. This disposes of masking, keyed frame schedules and temporal secret sharing in one step, and it forces the shape of any solution: the reader must hold a physical element that makes their optical path differ from the camera's.

Construction 2, against the camera. Give the reader a shutter synchronised to the display, passing half the frames. Run a four-frame cycle at 240 Hz:

A = L + d          passed by the shutter
B = L - d          passed
X = (1-L) + e      blocked
Y = (1-L) - e      blocked

(A + B) / 2         = L      the reader sees the true page
(A + B + X + Y) / 4 = 1/2    uniform grey, exactly, pixel by pixel

The second identity holds independently of the masks, because L + (1−L) = 1 everywhere. A capture spanning whole cycles therefore contains no spatial information — not degraded information, none. An ordinary camera at 1/30 s integrates eight display frames, which is two whole cycles. §5.9 reports what that measures out to.

Construction 3, the aperture bound. Render true text only inside a small window and fill the rest of the frame with decoy text. Any single capture then contains only the window's worth of true content, and the bound is on information present rather than on information obscured, so no image processing reaches past it. One detail matters and is easy to get wrong: the region outside the aperture must carry different information, not faint information. Attenuating the true text by a factor of twelve still lost the whole page, because ordinary autocontrast restores it.

Costs, which are real and fall on the reader. Construction 1 requires a 2:1 contrast ratio. Construction 2 halves the duty cycle, so the panel must run brighter, and needs 240 Hz hardware plus a shutter. Most seriously, frame alternation is a seizure and migraine trigger for photosensitive readers: it requires a warning, an opt-out, and an alternative route, on the same reasoning that keeps a wall-clock floor out of the default policy in §5.8. None of this applies to paper, which keeps only the chaff decoy and the kerning fingerprint.

5.2 Envelope

Overhead is constant at 1,660 bytes regardless of document size — ML-KEM-768 contributes a 1,088-byte ciphertext, X25519 32 bytes, and the remainder is the policy, nonces, wrapped key and signature. Sealing 10 MB took 136 ms; unsealing took 15.7 ms, i.e. 636 MB/s, which means the cryptography is not the bottleneck for any realistic document. Device key generation (both keypairs) took 5.0 ms.

The adversarial tests matter more than the timings:

  • Fail-closed on every posture predicate. Five predicates were violated one at a time; all five denials occurred before any key material was derived.
  • Policy tampering with signature stripping — rejected at signature verification.
  • Policy downgrade with a valid re-signature, modelling an adversary who has compromised the distributor's signing key — rejected at InvalidTag, i.e. the AEAD unwrap failed because the KEK no longer reproduced. This is the property that distinguishes the design from conventional signed-policy IRM: the policy is cryptographically load-bearing, not advisory.

5.3 Membrane

Inside the membrane, socket creation failed with EPERM for AF_INET, AF_UNIX and AF_NETLINK — the last matters because netlink is a common overlooked path to host configuration. An outbound HTTP request failed; curl executed as a child process also failed, confirming the filter is inherited across execve and therefore covers a downstream renderer or agent runtime.

The legitimate work was unaffected: rendering the protected PDF inside the membrane took 419 ms against a 456 ms unconfined baseline — within run-to-run noise, so the enforcement cost is not measurable at this granularity. Total child setup plus probe plus render was 552 ms. The Landlock probe returned ENOSYS on the 6.18.5 test kernel and was reported as unavailable rather than silently skipped.

5.4 Chaff

We rendered a one-page privileged legal memorandum and attacked it with the three text-extraction libraries that dominate real document pipelines, plus the rasterise-and-OCR path.

Generic content-word overlap between the extracted decoy and the true document was 0.133, entirely from everyday vocabulary that both texts share ("assessment", "structured", "existing"). On the metric that matters — identifiers, amounts and privileged terms — recovery was zero.

This is the empirical argument for design principle 4. The prior-art technique and the CLOISTER technique are equally good at withholding content from a text extractor; they differ entirely in whether the extractor notices.

The cost of forcing the vision path. The true document is ~493 text tokens. Rasterised at 200 dpi, one page is ~4,987 image tokens — a 10.1× inference-cost multiplier, plus OCR error, plus loss of document structure, plus the fact that most automated pipelines never attempt it. For an adversary processing one document this is an inconvenience. For an adversary processing ten thousand, it is a budget line.

5.5 Tracing

Code lengths follow m ≈ 4.93 c² ln(1/ε₁): 273 bits for a coalition of 2, 1,703 for 5, 6,812 for 10, at ε₁ = 10⁻⁶. With 1,000 recipients and the full document recovered, all five collusion attacks — majority, minority, coin-flip, all-ones and interleaving — were traced with probability 1.000 and zero false accusations.

Finding 1 — a one-sided accusation test is blind to the minority attack

Our first implementation accused on S > Zσ. Against the minority-voting attack it named 0.000 colluders — a complete failure, not a degradation, because minority voting produces a negatively correlated sequence that a one-sided test cannot see. Switching to a two-sided test on |S| restored detection to 3.517 of 5 colluders named with zero false accusations. Any deployment that copies the textbook one-sided formulation inherits this hole.

Finding 2 — the accusation threshold must scale with the roster

At 1,000 recipients, a 5σ threshold produced no false accusations. At 50,000 recipients — a realistic university — the same threshold produced 0.21 false accusations per trial, because the test is applied once per candidate and the multiple-comparisons burden grows with the roster. Raising the threshold to 6σ removed false accusations but collapsed detection to 48%, since the code was sized for the smaller population. The correct fix is to size the code for the roster: at m = 2,555 bits and 6σ, 50,000 recipients gave detection 1.000 with zero false accusations across 150 trials of every attack. The same effect appears when a code is starved by a short fragment: at R=1 and a 5% fragment the test produced 0.32 false accusations per trial while detecting essentially nothing. False accusation is the failure mode that matters here, and in both cases it is a parameter-selection problem that a naive deployment gets wrong.

5.6 The analog channel, measured

Section 2.2 asserted that a photograph of a CLOISTER-rendered page still carries its fingerprint. That claim was unmeasured in the first draft, and it is the load-bearing one for the whole attribution argument, so we built the channel and attacked it.

Each inter-word gap is displaced by a sub-perceptual amount, taken in pairs that sum to a constant: for a 1 bit the pair becomes (base + d, base − d), for a 0 the reverse. Line length is therefore invariant and displacement cannot accumulate along the line, so the right margin never moves and the perturbation stays strictly local. Detection compares the two gaps of each pair, which also cancels any global scaling introduced by printing or photographing. At 11 pt, d = 0.275 pt — 7.9% of a space advance — and one Letter page of running text carries 122 code positions.

Extraction does not segment words out of the image. The document owner holds the master, so the detector computes each word's expected window analytically from the layout and takes an intensity-weighted centroid inside it. This matters more than it sounds: our first two detectors tried to find words by ink connectivity, and both failed at chance, because a single split or merged glyph shifts every subsequent gap index and inverts the bits that follow. The analytic window removes that failure mode entirely.

End to end. We embedded one recipient's Tardos codeword, rendered the page, and put it through a simulated phone photograph — 1.3° rotation, 0.8 px blur, sensor noise, JPEG quality 70. All 122 positions on the page were recovered with zero bit errors, and the accusation named the correct recipient out of 1,000 with no false accusations.

Finding 3 — at this observation count the textbook threshold is unsafe

One page yields 122 observed positions, and at that count the Tardos score is not reliably Gaussian: its tail is driven by however many small pi the code happened to draw. A fixed 5σ threshold produced 0.188 false accusations per trial. Worse, the behaviour is not stable across code realisations — over 24 independently drawn codes at m = 69, detection ranged from 0.03 to 0.95 at the same nominal parameters. The fix is to calibrate the threshold against each code's own simulated null distribution at a chosen family-wise rate, and to screen candidate codes at generation time. Calibration drives false accusations to zero; the realisation still has to be chosen deliberately rather than assumed.

5.7 The ingestion oracle, and why it is withdrawn

The oracle was the one component whose value depended on an unmeasured empirical claim, so it was the one most worth measuring. We trained a character-level neural language model where the ground truth is known — a canary of fixed format inserted into the corpus a controlled number of times — and measured the canary's exposure after training, following the method of Carlini et al.[18]

Two methodological points first, because they determine whether the numbers mean anything. The gradients were verified numerically to a worst-case relative error of 5×10−8; a silent gradient bug would have produced whatever answer we went looking for. And the canary format was chosen small enough — 100,000 candidates — that the true canary's rank is computed exactly against every alternative rather than estimated from a fitted tail.

Finding 4 — an exposure figure alone is not evidence

In one control run a canary that had never been inserted scored 3.8 bits of exposure, because some digit strings are a priori more probable than others. Any oracle that reported that number as a finding would be manufacturing evidence. Under the null the true canary is exchangeable with every other candidate, so its rank is uniform and P(exposure ≥ x) = 2−x exactly — the p-value is analytic. Claiming ingestion at p < 0.001 therefore requires about ten bits, and no smaller figure is worth reporting.

The conditions favoured the oracle and it still failed. The corpus was small and repetitive, and the models reached a training perplexity of 1.08–1.18 — they had very nearly memorised everything they were shown, which is the most generous regime imaginable for canary recovery. A first sweep varying insertion count from 1 to 64 was uninformative for exactly that reason: every multiplicity gave perfect exposure, a ceiling effect rather than a result. Only when compute was fixed and the corpus grown — the condition a frontier model actually trains under — did the relationship become visible.

The second reason is architectural and needed no experiment. The oracle detects training-time ingestion: it asks whether a document was in the corpus. The canonical threat in this paper is inference-time — an associate uploads a privileged memorandum to a chatbot, a coding assistant reads a repository. None of that touches the weights, so there is nothing for an oracle to find. The component was aimed at scraping, which matters to publishers and authors, and not at the incident that motivates every user described in §1.1. That mismatch should have been caught in design review rather than in a measurement.

What replaces it. Nothing new is required, because the decoy already does the job for the threat that matters. If a model's output reproduces a document's per-recipient decoy, that is direct evidence of ingestion, it identifies which copy was ingested, it works at inference time, and it needs no access to the model's weights or training set. The capability the oracle was invented to provide already exists in Layer D, one section earlier.

5.8 Authorship provenance

Layer A was specified in §4.6 and has since been built, including the part the earlier draft deferred: the zero-knowledge disclosure. A student proves statements such as "no single insertion in my edit trail exceeded 400 characters" using Pedersen commitments and bit-decomposition range proofs in a 2048-bit group with a 256-bit prime-order subgroup. Proving takes about 350 ms and verification about the same, each proof is 16 KB, and a three-predicate credential is 54 KB. Seven forgery attempts — retargeting the bound, tampering with either commitment, mutating a response, reordering and dropping bits, replaying under a different context — were all rejected, and the prover refuses to attempt a false statement rather than emitting a proof that will not verify.

The architecture has to solve two opposed problems, and conflating them is the trap. Zero-knowledge proofs give the student privacy but supply no integrity whatsoever: an author could commit to whatever statistics suited them and prove things about those. Integrity comes from elsewhere — an attested editor computes the statistics, commits to them, and signs the commitments alongside the trail root and the submission hash. The proofs then bind to values the author cannot change. A design that shipped only the proofs would look cryptographic and establish nothing.

A privacy audit of the output found and removed a leak: the number of edit events was being repeated in cleartext in the attestation body, although it was already committed. After that, of 861 recorded edit events, zero timestamps and zero statistic values appear anywhere in the credential. What the instructor learns is the policy bounds, pass or fail against each, the submission hash, the trail root, and which editor signed it.

Finding 5 — a wall-clock floor is a false-accusation machine

The obvious predicate to add is a minimum elapsed time, and measuring it removed it from the default policy. Two simulated honest sessions producing identical output took 65 minutes and 3 minutes; a thirty-minute floor passes the first and fails the second. The second is a fluent writer, not a cheat. A floor penalises fluency, rewards leaving the editor open, and reproduces exactly the harm that §1.3 criticises detectors for. It ships disabled, behind an explicit flag, with the caveat attached. Rhythm statistics were excluded for the same reason and are worse: they misfire on dictation, on motor impairment, and on anyone drafting in a second language.

5.9 The display layer, measured

Every figure here is a true-content recovery against a page rendered by the four-frame cycle of §4.7, scored by running Tesseract on the capture with autocontrast applied — the attacker is given every advantage the harness can give.

Finding 6 — a keyed frame schedule is worth nothing

The obvious hardening is to keep the frame schedule secret so an adversary does not know which frames to combine. It fails, and not marginally: candidate combinations can be scored by "does the result read as text", which is a trivial test, so the search stays O(n²) over frame pairs and finishes in seconds. Secrecy of the schedule is not a security parameter. The only quantity that helps is how many frames the adversary's sensor can isolate.

The aperture bound behaves differently, and it is the only construction in this section whose guarantee is not contingent on the adversary's equipment. At apertures of 12 to 60 characters, a single capture recovered 0.053 to 0.067 of the document's content words and would need 33 to 165 separate captures to cover one page. That holds because the true text is absent from the frame outside the window, so there is nothing for a better attack to find. Its cost is borne in reading comfort, and we have not measured that.

5.10 Locking the numbers down, and what that turned up

Every claim above is now a named test, and every bug measurement found is a named regression test — 52 in total. The regression tests are built to an unusual rule, because the ordinary kind would not have helped here: each one registers two implementations, the fixed one and a faithful reconstruction of the original broken one, and asserts that the broken one fails. If it passes, the test is reported TOOTHLESS and the suite exits non-zero. This is mutation testing narrowed to the mutations that actually occurred, which is the subset already proven able to survive review. The harness also snapshots module state around every test, because a mutation is installed by monkeypatching and a mistaken restore does not look like a leak — it looks like five unrelated tests regressing at once, in another file.

Writing it found three more defects, which is the honest argument for having done it.

Finding 7 — the photograph model was the weak link, not the detector

Every degradation ladder in §5.4 held the page at full white. That hides two things at once: the uint8 clip discards the negative half of the sensor noise, and there is no paper pedestal for a threshold measured from zero to fall below. Give the detector grey, unevenly lit paper — an ordinary phone photograph — and it failed at chance, while its diagnostics still looked healthy. The tell was a median gap margin of 5.6 px against a 1.09 px signal: measurement error being read as signal. Two fixes were needed. A quadratic illumination surface is fitted from low-percentile samples and subtracted (six coefficients — enough for a ramp and the quadratic bowl of vignetting, too few to follow a text line), and what remains is thresholded relative to the local paper level with a noise-floor term. Re-measured across eight lighting conditions from flatbed scan to a dim room with off-centre vignetting, three recipients each: 24 of 24 traced, 0 false accusations, bit error rate 0.0% in 20 of 24 and worst 2.9%.

The general lesson is uncomfortable and worth stating plainly: the degradation model was written by the same people who wrote the detector, and it was flattering in a way nobody noticed for an entire measurement campaign. A simulated attack ladder is a claim about the adversary, not a measurement of one.

Finding 8 — embedded redundancy was being thrown away on recovery

The renderer cycles the codeword through however many gaps the document provides, so a page-filling page carries a 69-bit code about three times over. The detector assigned each position as it read it, so the last measurement silently overwrote the earlier ones and the redundancy bought nothing. Combining the repeats as signed evidence rather than as a majority vote on hard bits — a gap measured with a 2 px margin deserves more weight than one measured with 0.1 px — raises the combined margin from 1.01 px to 3.10 px, exactly the redundancy factor, and cuts the bit error rate on a dim photograph by roughly three.

Finding 9 — a stale render is a wrong accusation

The rasteriser collected every image matching its output prefix, and the trace command reuses a fixed working directory. A one-page brief traced after an eight-page one therefore saw eight reference pages, seven belonging to a different document, and matched the evidence against whichever fitted best. Nothing warned. This is the worst class of bug this system can have, because its output is an accusation against a named person, and it was found by running the command-line tool twice in a row rather than by any amount of reading. The detector now also warns when gap margins are far larger than the embedded displacement, which is the signature of a misregistered page in general rather than of this one cause.

5.11 What these numbers do and do not establish

They establish that the mechanisms work as specified, on a real document, against the tools an adversary reaches for first. They do not establish that a determined adversary cannot recover the document — the OCR row of Figure 2 says plainly that one can. They measure OCR, not a multimodal model, which would likely do at least as well. They include no user study. The layer most important to the academic case is built but not deployable: it depends on an attested editor producing a real edit trail, and every measurement in §5.8 used synthesised trails instead. And after Finding 7, the sentence that deserves the most weight is this one: every degradation figure here is a simulation, and simulations written alongside the detector they test have already proven able to flatter it for months. Photograph real printed copies before relying on any of the tracing numbers.

Strip the watermark by diffing several copiesA3Traced. This is exactly the collusion model Tardos codes are proven against; §5.5 measures five attack strategies. Residual: coalitions materially larger than the c the code was sized for.
Retype the documentA2Partially traced. Kerning and glyph channels are destroyed; the lexical channel survives verbatim retyping. Heavy paraphrase defeats tracing. Effort scales linearly with length, which is the deterrent.
Photograph the screen, auto exposureA2Defeated under Layer V with the shutter: any exposure spanning whole display cycles records uniform grey, exactly (§5.9). Without Layer V, not prevented but traced by the kerning channel.
Photograph with a deliberate short shutter, then unmaskA3Not prevented, traced. Isolating a single display frame and applying cell-median unmasking recovers the page. Requires knowing the technique, setting a manual shutter around 1/500 s, and implementing a grid search — a materially higher bar than pressing a key, and the kerning fingerprint still survives.
Record the reading session on videoA3Bounded, not prevented. No display-only scheme can beat a full recording (§4.7), and the shutter cycle only helps if the sensor cannot isolate frames. The aperture bound caps what each capture holds; per-session frame watermarking makes the recording attributable.
Patch the viewer to skip the posture checkA3Defeated. The check is not a branch in the client; the posture digest is in the KDF transcript. A patched viewer derives a key that does not decrypt (§5.2).
Compromise the distributor's signing keyA3Defeated for existing envelopes. Verified: re-signing a downgraded policy still fails AEAD unwrap. Newly issued envelopes are of course compromised.
Extract keys from the viewer's memoryA3/A4Raised. ptrace denied, DUMPABLE 0, hardware-sealed leases with short lifetimes. A kernel-privileged adversary (A4) succeeds; not defended.
Ambient OS assistant captures the screenA1Defeated on Windows and macOS via capture exclusion; Windows' documented Recall opt-out is the same call.[4] Partial on Wayland, none on X11.
Local agent / MCP server reads the fileA1Defeated. The envelope does not open for a process that cannot satisfy the posture policy, and an agent needs network egress by construction.
Framing an innocent recipientA3Bounded, not eliminated. The ε₁ bound covers statistical false accusation, and §5.5's second finding shows the threshold must scale with roster size. It does not cover a recipient who deliberately re-embeds another's fingerprint — an open problem (§13).
Denial of service on the lease brokerA3Mitigated. Lease lifetimes permit offline work; a cached lease survives broker outage for its validity window. Availability is a genuine cost of revocability.

10  Ethics, law and misuse

10.1 Authorship provenance is surveillance unless designed not to be

A system that records how a student writes is a system that can be turned against them, and the history of proctoring technology is not reassuring. Three commitments are therefore architectural rather than policy: the edit trail never leaves the student's device; only predicates over it are disclosed, never content or timings; and the credential must be verifiable by the student before submission, so nobody is surprised by what their own tool asserted about them. A student must also be able to decline and be offered an alternative assessment route — a mandatory provenance regime with no opt-out will produce exactly the false-accusation harms it was meant to replace. We would rather ship a weaker guarantee than a stronger surveillance apparatus.

10.2 Why CLOISTER contains no prompt injection

An obvious temptation is invisible text instructing a model to refuse. We reject it, for four reasons that we think are dispositive. It is an attack on a third party's system rather than a protection of your own document. It is unreliable, and unreliable security is worse than none because it produces false confidence. It degrades legitimate accessible reading. And it may expose the sender to liability for interfering with a computer system they do not own. The chaff layer's decoys are therefore inert: they contain no instructions, only innocuous prose. This is a deliberate line and we think any serious product in this space has to draw it.

10.3 Accessibility is a first-class requirement, not an exception

A blind reader using a screen reader relies on exactly the text layer that chaff replaces. Handled badly, this technique locks disabled readers out of documents everyone else can read, which is both wrong and in many jurisdictions unlawful. The design answer: assistive technology is a first-class attested client. Under the desktop and managed postures, a screen reader that satisfies the posture policy receives the true text through the same lease mechanism as the renderer. Under the format-only posture — where no such gate exists — the document must ship with an accessible variant available on request, and the exported artefact should say so on its face. Any deployment that cannot meet this should not use the chaff layer.

10.4 Dual use

Tools that make documents hard for machines to read and hard to attribute can serve people evading legitimate scrutiny as easily as people protecting privileged material. The mitigations are structural: the transparency log makes access history auditable rather than deniable; envelopes carry a plaintext-visible policy so a recipient always knows what they hold; and legal-hold and lawful-process exemptions belong in the policy vocabulary from the first version, not bolted on later. A system marketed to lawyers that made discovery obligations harder to meet would be a liability to its own users.

11  Regulatory and market context

11.1 The obligations that create demand

  • Attorney duties. ABA Formal Opinion 512 (July 2024) is the reference point: lawyers using generative AI must protect client confidentiality, and self-learning tools that may expose client information require informed consent.[5] "We encrypted it and hoped" is not a defensible answer; an auditable access log is.
  • Discoverability of AI conversations. The court-ordered production of roughly 20 million de-identified ChatGPT conversations in the New York Times litigation[2] established concretely what was previously theoretical: a prompt is a record, and records are discoverable. Pasting privileged text into a consumer assistant creates a new evidentiary surface outside the firm's control. This is the single most persuasive fact in a legal-sector sales conversation.
  • EU AI Act. Prohibitions and AI-literacy duties have applied since 2 February 2025; general-purpose model obligations since 2 August 2025; Article 50 transparency duties arrive 2 August 2026. The Digital Omnibus deferred high-risk obligations — Annex III standalone systems to 2 December 2027 and Annex I embedded systems to 2 August 2028 — and added a new Article 5 prohibition effective 2 December 2026.[14] The deferral is worth stating plainly rather than overselling: the near-term compliance driver is transparency and provenance, not high-risk conformity assessment.
  • Trade-secret law. Protection is conditioned on reasonable measures to maintain secrecy. As uncontrolled AI ingestion becomes foreseeable, the definition of "reasonable" moves, and a documented technical control becomes evidence.

11.2 The competitive gap

The AI-security category is well funded — SentinelOne's acquisition of Prompt Security, announced August 2025 at a reported ~$250M, is the clearest marker — and almost all of it sits at the same architectural position: a gateway or browser extension on a managed device inside a managed network. That is a real product solving a real problem, and it is structurally incapable of protecting a document after it has been sent to someone else.

CLOISTER's position is the complement, not the competitor: protection that travels with the file. The two compose naturally — a gateway that recognises CLOISTER envelopes can enforce policy on egress, and CLOISTER can enforce policy where no gateway exists. The wedge is the recipient outside your perimeter, which is where both the professor's and the lawyer's actual problem lives, and which nobody is currently serving.

13  Limitations and open problems

Acknowledged limitations

  • Vision models defeat the chaff layer. Figure 2 shows OCR recovering 100% of sensitive terms. Chaff imposes cost and removes the escalation trigger; it does not stop a determined adversary who rasterises.
  • The analog hole is open, by construction and permanently.
  • A4 adversaries win. Kernel privilege on the reading device defeats the membrane. Confidential-computing enclaves on the client would help and are not practically available for this use case today.
  • X11 cannot be secured by the operating system. Layer V now gives a platform-independent partial answer for the single-screenshot case (§5.9), but a bare X11 session still offers no capture exclusion, and Layer V is not a substitute for it.
  • Single-frame secrecy is impossible at readable contrast, and §4.7 gives the argument rather than treating it as an engineering gap. Everything in the display layer except the aperture bound is cost imposition.
  • The display layer asks the reader to pay. A 2:1 contrast ratio, a halved duty cycle, 240 Hz hardware, a shutter — and flicker, which is a seizure and migraine trigger. It must ship disabled with an opt-out and an alternative route, and we have run no usability or safety study.
  • One layer was withdrawn, and one depends on a component we have not built. The ingestion oracle was measured and abandoned (§5.7). Authorship provenance is implemented (§5.8) but is worthless without an attested editor producing the trail, and that editor does not exist yet — everything measured so far used synthesised trails.
  • No usability evidence. Every result here is a machine measurement. The dominant failure mode of document security products is that people turn them off, and we have not measured that at all.
  • The decoy is not yet grammatical. §4.4 documents the gap and the fix.
  • The analog channel needs deskewing and a calibrated threshold. Uncorrected rotation beyond about a degree destroys it, and the accusation threshold cannot be taken from the textbook at single-page observation counts (§5.6, finding 3).
  • One page does not trace a coalition. Single-leaker attribution from a photograph is solid; five colluders need roughly fourteen recovered pages.

Open problems we cannot currently solve

  • Watermark survival through model-mediated paraphrase. If a recipient has a model rewrite the content, every embedding channel we have is destroyed while the semantics survive. Semantic watermarking that survives paraphrase is an active research area and, if solved, would be the single most valuable addition to this design.
  • Fingerprint framing. A recipient who understands the kerning channel could re-embed another recipient's codeword. Cryptographically binding the fingerprint to something the recipient cannot forge — without giving them the extraction key — is unsolved here.
  • Statistical power of the ingestion oracle — resolved, and the answer was no. Measured in §5.7. The detection floor sits about seven orders of magnitude above the relevant density, and the mechanism addressed the wrong ingestion path in any case. This line item is retained rather than deleted so the record shows what was claimed and what happened to it.
  • PCR brittleness in hardware sealing. TPM policies bound to measurement registers break on legitimate firmware updates. Policy authorisation helps; the operational burden is real and is why many products quietly stop using it.
  • Accessibility under the format-only posture. With no attestation gate, we cannot distinguish a screen reader from a scraper. The out-of-band accessible variant is a process answer, not a technical one, and we are not satisfied with it.

14  Conclusion

The instinct that motivated this work — that files need protection from being "dumped into AI models," and that content-side pleading cannot deliver it — is correct, and it points at a real architectural gap. Every deployed control today assumes the defender owns the environment where the document is opened. The documents that matter most are precisely the ones sent somewhere else.

CLOISTER's answer is to stop asking who is opening a document and start asking whether the runtime requesting the key has any path by which the plaintext could leave — and to make that question cryptographically load-bearing, so that a client which lies about it derives a key that does not work. Where prevention is impossible because the document must travel, it makes the machine-readable copy fluently wrong rather than obviously broken, so that automated pipelines stop instead of escalating. And it makes every copy unique, so the eventual leak has a name.

The measurements support the specific claims made and no more: zero of twenty-four sensitive terms recovered by the extraction libraries that real pipelines use; a decoy that those pipelines cannot detect; a policy binding that survives compromise of the signing key; sixteen egress paths closed at no measurable performance cost; a leaked paragraph — five percent of a document — sufficient to name one of five colluders at least 96% of the time with no false accusations in 3,000 trials; and a fingerprint that survives being photographed, recovered with zero bit errors from a simulated phone photo and naming the right recipient out of a thousand. Two of those results only exist because trying to break the design revealed that the textbook version was wrong.

What remains is the analog hole, which will remain, and two layers that are still designs. The honest claim is not that CLOISTER makes documents unreadable to machines. It is that it makes the easy paths fail, the hard paths expensive, and all of them attributable — which is the most that can be true, and considerably more than anything currently available to the professor with an exam to send or the associate with a privileged memo to file.

  nonce : bstr .size 12

}

Header = {
  suite  : tstr                  ; "CLOISTER-v1-X25519+MLKEM768-AES256GCM-SHA384"
  policy : Policy
  kem    : {
    ct_x25519    : bstr .size 32
    ct_mlkem768  : bstr .size 1088
    nonce        : bstr .size 12
    wrapped_ck   : bstr .size 48 ; AES-256-GCM(ss, CK), AAD = H(policy)
  }
}

Policy = {
  matter            : tstr
  require           : { * tstr => bool }   ; posture predicates, all must hold
  lease_seconds     : uint
  not_after         : tstr                 ; RFC 3339
  fingerprint_seed_id : tstr               ; per-recipient; keys chaff + kerning
  transparency_log  : tstr                 ; append-only Merkle log endpoint
}

Derivation
  ss  = HKDF-SHA384(ikm = ss_x ‖ ss_k ‖ ct_x ‖ ct_k ‖ H(policy) ‖ suite,
                    info = "cloister/kek", L = 32)
  CK  = AESGCM-Decrypt(ss, nonce, wrapped_ck, aad = H(policy))
  D   = AESGCM-Decrypt(CK, nonce, body,       aad = H(hdr))

Release rule
  derive(ss) is attempted only after the local broker verifies every predicate in
  policy.require against live runtime evidence and a valid hardware-sealed lease.
  Posture first, key second — the ordering is the security property.
